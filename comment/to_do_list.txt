앞으로 해야 할 것

나는 지금부터는 기능 추가보다 안정성 → 스케줄 기능 → 설정 편의성 → GUI 순서로 가는 걸 추천해.

🔴 1순위 — 자동화 Chrome 잔여 프로세스 문제 해결

이번에 실제로 발견한 문제야.

방송이 끝나거나 중간에 실패했을 때 OKBO_automation Chrome이 남아 있으면 다음 실행에서:

프레젠테이션 시작 중…

에서 멈출 가능성이 확인됐어.

현재는 우리가 직접:

Stop-Process -Id 2632 -Force

해서 해결했지.

다음 작업은 이걸 프로그램이 알아서 처리하게 만드는 것.

단, 중요한 조건:

일반 Chrome은 절대로 종료하지 않는다.

오직:

OKBO_automation

을 사용하는 Chrome만 찾아서 종료하도록 만들면 돼.

이건 실제 자동방송을 운영하려면 상당히 중요한 작업이라고 봐.

🟠 2순위 — 스케줄 기능 제대로 완성

현재는 "다음 방송 하나를 찾아 실행"하는 수준이야.

여기서 실제 운영용으로 발전시키면:

월요일
  10:00 → 동영상 1
  14:00 → 동영상 2
  20:00 → 동영상 3

화요일
  09:00 → 동영상 1
  ...

처럼 schedule.json에 여러 개를 넣고 계속 반복 실행하는 구조가 필요해.

즉 지금:

다음 방송 1개 실행
        ↓
프로그램 종료

에서

다음 방송 찾기
        ↓
방송
        ↓
방송 종료
        ↓
다음 방송 찾기
        ↓
계속 반복

으로 바꾸는 거야.

이게 실제 스케줄러의 핵심 완성 단계야.

🟡 3순위 — 방송 실패 처리

예를 들어:

Chrome 실행 실패
CDP 연결 실패
Meet 입장 실패
동영상 탭 생성 실패
공유 시작 실패
동영상 재생 실패

등이 생겼을 때 현재는 subprocess.run(check=True) 때문에 오류가 올라오면서 종료돼.

나중에는:

방송 실패
 ↓
오류 기록
 ↓
자동화 Chrome 정리
 ↓
다음 예약 방송 대기

같은 구조가 필요해.

특히 스케줄러가 한 번 실패했다고 전체 스케줄러가 죽으면 안 돼.

🟡 4순위 — 설정 파일 정리

현재 schedule.json에 방송 설정이 들어가 있으니까 나중에는 이런 것들을 좀 더 체계화할 수 있어.

예:

{
    "videos": {
        "1": "...",
        "2": "...",
        "3": "..."
    },
    "schedule": {
        "monday": [
            {
                "time": "10:00:00",
                "video": "1"
            }
        ]
    }
}

여기에 필요하면:

방송 활성/비활성
요일별 설정
테스트/실제 모드
방송 전 대기시간
방송 후 대기시간

등을 관리할 수 있어.

다만 지금 당장 설정을 크게 뜯어고칠 필요는 없어.

🟢 5순위 — 방송 상태 표시

전에 이야기했던 이것도 여기에 들어가.

예를 들어 방송 전:

잠시 후 동영상 공유가 시작됩니다.
10초 남았습니다.

방송 종료 전:

방송이 종료됩니다.
10초 후 자동으로 나갑니다.

같은 안내를 Chrome 화면에 표시하는 것.

기능 자체는 유용하지만 현재 핵심 안정성보다 우선순위는 낮아.

🟢 6순위 — GUI

최종적으로는 지금 PowerShell에서:

python scheduler.py

하는 대신

┌─────────────────────────────┐
│     Google Meet 방송 관리    │
│                             │
│  다음 방송  15:30           │
│  동영상     movie_3.mp4     │
│                             │
│  [ 방송 시작 ]              │
│  [ 스케줄 관리 ]            │
│  [ 설정 ]                   │
│                             │
└─────────────────────────────┘

같은 형태로 만들 수 있어.

하지만 GUI는 마지막에 하는 게 좋아.

지금 구조가 아직 바뀌는 중이라 GUI를 먼저 만들면 나중에 GUI까지 같이 수정해야 하거든.

내가 보는 전체 우선순위
우선순위	작업	중요도
🔴 1	자동화 Chrome 잔여 프로세스 자동 정리	매우 높음
🔴 2	스케줄러 반복 실행 구조	매우 높음
🟠 3	방송 실패/예외 처리	높음
🟡 4	schedule.json 설정 체계화	중간
🟢 5	방송 전/후 안내 표시	낮음
🟢 6	GUI 제작	마지막

그리고 지금 당장 다음 작업은 1번으로 잡는 게 좋아.
